Security & Privacy

Built with hard floors,
not soft promises.

Prexi processes data in-flight, stores nothing, and protects sensitive conversations at the architecture level — not the policy level.

01Data Handling

Zero persistence.

No conversation storage

Conversations are processed entirely in memory. After the compress → forward pipeline completes, no message content is retained. No logs, no buffers, no backups.

API keys never stored in logs

Your LLM provider API key (x-llm-key) is forwarded to the upstream model and immediately discarded. It never touches our database. Prexi keys are stored as SHA-256 hashes — not plaintext.

Semantic cache — anonymised

The semantic cache stores embedding vectors, not text. A cache hit returns a compressed context by similarity — the original conversation text is never stored.

Usage logs — metadata only

We log: timestamp, key ID, endpoint, tokens saved, domain, cache hit status. No message content, no user identifiers, no IP addresses beyond rate-limiting (discarded after 1 minute).

02Protected Zones

Architectural, not configurable.

Hard floors — cannot be disabled
MedicalLegalCrisis

When DistilBERT classifies a conversation as medical, legal, or crisis — compression is disabled at the function call level. The check happens inside compressHistory() before any other processing. This cannot be overridden by API callers, admin keys, subscription tier, or configuration.

No monetization of protected zones

Protected conversations are not counted toward your token quota. We do not run ads, sell insights, or use protected conversation data for any purpose.

Response header evidence

Every response includes x-cts-protected: true/false and x-cts-domain so you can verify the classification at the application level.

03Infrastructure

Where your data runs.

Google Cloud Run

Serverless containers, auto-scaling, 4GiB memory, min-instances=1 for consistent latency. No shared state between instances.

GCP region: asia-south1

Default region is Hyderabad (asia-south1). Enterprise customers can request US-East, EU-West, or bring their own VPC.

TLS 1.3 everywhere

All traffic encrypted in transit via TLS 1.3. HSTS headers enforced. No HTTP fallback on any production endpoint.

Firebase Firestore

API key metadata stored in Firestore (hashed keys, quota counters, usage metadata). No conversation content ever reaches the database.

Rate limiting per key

Per-key rate limits enforced in memory per Cloud Run instance. DDoS protection via GCP Load Balancer. Burst capacity handled via Cloud Armor.

Dependency audit

Open source dependency manifest available on request. We run npm audit on every build. Critical CVEs block deployments.

04Responsible Disclosure

Found a vulnerability?

Report a vulnerability →

We take security reports seriously. Email team@yudi.co.in with a description of the issue and steps to reproduce. We'll acknowledge within 24 hours and work to resolve within 7 days for critical issues.

Please do not publicly disclose the vulnerability until we've had a chance to address it. We don't have a formal bug bounty program yet — but we'll acknowledge your contribution publicly if you'd like.
